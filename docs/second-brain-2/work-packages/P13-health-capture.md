# P13 — 건강·수면 입력·결측·권한 철회

명세 등록 / 제품 구현·건강정보 수집·실기기 시험 NOT_RUN. Refs #3. 선행 R2 인수와 종류별 명시 opt-in. P01 #5/P02 #6/P10 #14/P11 #15 공통 계약을 재사용한다. R3 / REQ-01·REQ-02·REQ-06·REQ-08 / Capture+Client+QA / 5–8인일 추정. 기준: 개발계획 4.3·5.3·13·16장. 원문 버전/hash는 #3.

## 목표와 한계
수면·걸음 수·심박·HRV를 사용자가 각각 허용한 경우에만 수집하고, 단위·출처·시각·결측을 보존해 기억과 타임라인에 제공한다. 의학적 진단·피로 확정·치료 권고를 생성하지 않는다. HealthKit 읽기 결과가 비었다는 사실만으로 권한 거부 또는 실제 기록 없음 중 하나를 단정하지 않는 계약을 유지한다. 구현 시 최신 공식 권한·배경 실행 계약을 확인한다.

## 입력 계약
source sample ID/version, device/source provenance, type, value/unit, start/end, observed/recorded time, timezone/precision, value_status/reason, scope/sensitivity/retention을 보존한다. 같은 표본 재전송은 멱등, 출처가 다른 표본은 근거 없이 동일 실측으로 합치지 않는다. 건강 원문은 기본 restricted/local-only다.

## 구현 체크리스트
- [ ] 실제 기기의 HealthKit 가용성·데이터 종류·권한·서명/entitlement를 P00 결과와 대조한다. 센서·기기·표본이 존재한다고 가정하지 않는다.
- [ ] 수면/걸음/심박/HRV 각각 수집 ON/OFF·보존기간·View 제공 범위를 설정한다. 전체 동의를 일괄 켜지 않는다.
- [ ] source sample 식별자와 증분 cursor/anchor, 삭제 이벤트를 기존 inbox/receipt/ledger 계보에 연결한다.
- [ ] 영속 접수 후 cursor를 전진시키고 오프라인 재전송·응답 유실·앱 재시작·동률 시각에서 표본을 잃지 않게 한다.
- [ ] type별 단위와 시간 범위·중복·수면 구간 겹침·여행 시간대·잘못된 수치 형식을 검증한다. 0, null, unavailable를 구분한다.
- [ ] 관측 데이터가 부족하면 coverage/insufficient_data를 표시한다. 빈 수면 기록을 0분 수면으로 집계하지 않는다.
- [ ] 여러 기기/앱 출처의 겹친 표본 집계 규칙을 명시하고 원본 출처를 보존한다. 임의 평균으로 충돌을 숨기지 않는다.
- [ ] 범위 밖 모델·로그·알림·그래프에 원문 수치를 보내지 않는다. Obsidian에는 사용자가 허용한 요약만 제공한다.
- [ ] 앱 내 수집 철회는 새 입력과 향후 조회·복제 정책에 반영한다. 이미 저장된 자료의 삭제 선택·보존을 구분하고 OS 읽기 권한 상태를 추측하지 않는다.
- [ ] 원문 삭제/정정/보존기간 만료를 타임라인·브리핑·View·캐시·백업 복구 계보에 전파한다.
- [ ] 실제 iPhone에서 권한 변경·재부여·오프라인·재접속·증분·결측을 검증하고 모형 fixture와 분리 보고한다.

## 코드·경계
기존 iPhone capture client, 기존 source adapter/ledger/정규화/원문 조회·삭제 경로를 확장한다. `records_health.py` 등은 신규 후보이며 실제 경로는 P00에서 고정한다. 서버가 HealthKit을 직접 읽는 것처럼 구현하지 않는다. 별도 건강 정본 DB, 모든 종류 자동 수집, 건강 점수/진단 모델은 제외한다. 현 PR diff는 이 명세 파일뿐이다.

## 적용·복구·완료
`health_capture` 기본 OFF, 종류별 제한 활성화. OFF해도 삭제·정정은 계속 처리하고 수락한 원본 상태를 보존한다. 권한 변경 실패를 성공이나 기록 없음으로 위장하지 않는다. 실제 기기/OS/app build, 종류별 sample·cursor·receipt 대조, 단위·결측 fixture, 정상/실패/철회·복구 로그, 독립 검토를 요구한다. 현재 구현·건강 수집·실기기·모델 실행 모두 NOT_RUN. 이 명세 등록은 건강정보 수집 동의가 아니다.
