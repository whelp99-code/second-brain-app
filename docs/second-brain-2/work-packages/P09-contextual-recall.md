# P09 — 상황별 회상·검색 평가

명세 등록 / 구현·평가 NOT_RUN. Refs #3. 선행 P05 #9, P08 #12; 모델 사용은 P10 인수 후. R2 / REQ-05·REQ-06 / Core+QA / 5–8인일 추정. 기준: 개발계획 10·12·16.1장. 원문 버전/hash는 #3.

## 목표
허용한 일정 전, 선택한 사건/프로젝트, 명시 질문에 관련된 기억을 근거와 함께 제공한다. 당시와 현재 결정을 구분하고 없는 기억과 검색 장애를 다른 상태로 알린다.

## 구현 체크리스트
- [ ] 트리거와 사용자가 허용한 scope/as_of/query를 고정한다. 모든 앱·화면·키 입력을 감시하지 않는다.
- [ ] 기존 lexical/semantic/hybrid/RRF 경로를 기준선으로 측정한다. `uses_fts=False`만 보고 결함을 확정하거나 true로 바꾸지 않는다.
- [ ] 접근 범위를 후보 모델 처리 전에 적용하고 시간·상태·정정·삭제 필터를 유지한다.
- [ ] 후보 record_id/digest/source/pinned generation을 재검증한다. 근거가 끊긴 결과를 확정 기억으로 반환하지 않는다.
- [ ] 출력은 기억 요점→지금 필요한 이유→당시/현재 차이→근거→정정으로 구성한다.
- [ ] no_data, retrieval_unavailable, stale, scope_denied와 축소 응답을 분리한다. 다른 프로젝트를 찾았다는 흔적도 노출하지 않는다.
- [ ] 선택 reranker는 원문 scope 필터 후에만 사용한다. RRF 점수를 확률로 표시하지 않는다.
- [ ] 변화/철회에 연결된 캐시 무효화와 같은 세대 조회를 보장한다. 모델 fallback도 P10 정책을 따른다.

## 300문항 평가 설계
정확 검색60, 한국어 띄어쓰기/동의어50, 시간·결정 변화60, 복수 출처40, 정정·삭제40, 답 없음30, 접근 범위20 = 300. 개발/평가/잠금 holdout을 분리하고 원출처/질문 중복으로 정답이 누출되지 않게 한다. 사용자 정답 검토 여부, 기대 source/span, 시점, 금지 답변을 레코드에 둔다.

Hit@5, MRR, 잘못된 시점 답변, 무근거 답변, 모름/거부 정확도, 검색 p50/p95, 모델 생성시간, 메모리·비용을 별도 측정한다. 같은 corpus/model/hardware/후보 수로 lexical과 새 경로를 비교한다. 품질 비열화·범위 누출0을 요구하고 효과 없는 단계는 OFF로 유지한다. p95 검색≤3초는 생성시간 제외 목표이며 현재 성능이 아니다.

## 코드·API
기존 `sb/search.py`, `sb/search_query.py`, `sb/hybrid_search.py`, `sb/memory_search.py`, 범위 검색·세대 검사와 config를 대조한다. 얇은 recall orchestration/버전형 route만 추가하며 새 LanceDB/graph DB/검색 서버를 필수화하지 않는다. read-only 회상 요청이 자동 실행·승인을 유발하지 않는다.

## 인수시험
AC-14: 과거 A→현재 B의 '당시/현재/왜 변경' 질의를 각각 올바른 원문과 연결. AC-15: 제목/snippet/노드/reranker 입력 포함 범위 밖 누출0. AC-09: 정정 직후 cache/recall에서 옛 사실 재사용 차단. AC-23: 악성 근거가 실행 지시로 바뀌지 않음. AC-24: 기존 공개 검색/MCP 계약 회귀. 모델 없음/벡터 없음/identity mismatch/인덱스 stale도 분리 시험한다.

## 적용·중단·완료
`contextual_recall`과 선택 검색 고도화는 독립 flag로 둔다. 기존 경로보다 품질/지연이 나쁘면 기존 검색으로 복귀하되 축소 상태를 알린다. 품질 수치를 만들어 채우거나 평가셋 정답을 바꿔 통과시키지 않는다. 현 diff는 이 문서 1개이며 구현/300문항 평가/실모델/실서비스 시험 모두 NOT_RUN. 실제 evaluation artifact·revision·환경·결과표·독립 검토가 필요하다.
