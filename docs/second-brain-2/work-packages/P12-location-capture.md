# P12 — 위치 수집·방문/이동 집계·프라이버시

명세 등록 / 제품 구현·위치 수집·실기기 시험 NOT_RUN. Refs #3. 선행: R2 인수와 사용자의 명시적 위치 opt-in. P01 #5/P02 #6/P10 #14/P11 #15의 계약·정책·운영 경계를 재사용한다. R3 / REQ-01·REQ-02·REQ-06·REQ-08 / Capture+Core+QA / 4–7인일 추정. 기준: 개발계획 5.3·11·13·16·17장. 원문 식별/hash는 #3.

## 목표
허용한 위치 입력을 영속 보관하고 정확도·누락·시간대를 고려해 방문/이동 사건으로 집계한다. GPS 좌표를 그대로 매번 모델에 보내거나 기록되지 않은 구간을 방문 사실로 만들어내지 않는다.

## 입력·상태 계약
Overland 형식 adapter를 우선 후보로 한다. 구현 시 실제 앱/버전/전송 schema/성공 응답 계약을 확인한다. 현재 명세가 앱 설치·백그라운드 수집 성공을 증명하지 않는다. source/device/item ID, source timestamp, 서버 접수 시각, 좌표와 정확도, 배치 ID, 원본 참조, 정책을 보존한다. 입력 오류/미허용/지연/정상 빈 구간을 구분한다.

## 구현 체크리스트
- [ ] 사용 목적·출처·정밀도·보존기간·단말 복제 범위를 opt-in으로 설정한다. 일시중지/해제/철회 동작을 제공한다.
- [ ] 기존 bounded inbox와 P02 receipt로 연결한다. 원본과 receipt의 영속 보존 이후에만 앱에 성공을 반환한다.
- [ ] 오프라인 batch 재전송·응답 유실·같은 좌표 반복·서로 다른 시각 사건을 멱등 처리한다. 좌표만으로 중복을 판정하지 않는다.
- [ ] 위경도 범위·정확도·타임스탬프·배치 크기·순서 역전·clock skew·원문 크기를 검증한다.
- [ ] 시간 간격·정확도·정지/이동 조건으로 결정적 구간을 집계하고 모든 임계값/알고리즘 버전을 기록한다.
- [ ] GPS 누락/저정확도/장시간 비관측은 unknown coverage로 남긴다. 일정 또는 주소 근접만으로 실제 방문/미팅을 확정하지 않는다.
- [ ] 정밀 좌표는 기본 restricted/local-only로 두고 Obsidian에는 허용한 장소 alias 또는 거친 구간만 제공한다. 로그·알림·그래프 제목으로 좌표를 우회 노출하지 않는다.
- [ ] 장소 alias 수정과 방문 구간 재집계를 가역적 개정으로 처리하고 P02 삭제/정정 계보를 유지한다.
- [ ] 예측용 duration은 출발/도착 근거·적격 여부·coverage를 포함해 P14로 전달한다. 불완전 구간을 실제 소요시간으로 채점하지 않는다.
- [ ] 실제 iPhone 백그라운드·오프라인·재시작·권한 변경·배터리·수집 지연을 측정하고 설정별 결과를 구분한다.

## 코드·인터페이스
기존 connector 자동발견 규칙에 맞는 `records_location.py` 등은 신규 후보다. 기존 인증·영속 접수·L3 정규화·L4 순수 집계·Vault writer를 재사용한다. 외부 노출 ingress/TLS/기기 토큰은 P00/P11의 허용된 경로만 사용한다. 새 위치 서버·모든 좌표 LLM 분석을 필수화하지 않는다. 현 PR 변경은 이 명세 문서 1개뿐이다.

## 적용·롤백·완료
`location_capture` 기본 OFF. R2 인수와 opt-in 이후 선택 기기·짧은 보존기간으로 시작한다. OFF는 새 수집을 중단하되 수락 자료·사용자 정정·삭제 의도를 보존한다. 위치 권한/배터리 설정을 이 PR 생성으로 변경하지 않는다. 실제 기기·OS·앱 버전·알고리즘 설정·receipt·coverage·배터리/지연·정상/실패/복구 로그와 독립 검토가 필요하다. 현재 모든 제품 구현·수집·시험 NOT_RUN.
