# P14 — 사전 예측 원장·실제 결과 연결·채점

명세 등록 / 제품 구현·예측·채점 시험 NOT_RUN. Refs #3. 선행: 적격 실제 사건 표본, P01 #5/P02 #6/P05 #9/P10 #14/P11 #15의 계약·정책·운영 gate. 위치 이동시간을 선택하면 P12 #16 입력 인수가 필요하지만 반복 업무시간을 선택한 경우 위치/건강 수집을 불필요하게 요구하지 않는다. R3 / REQ-07·REQ-06 / Core+QA / 4–6인일 추정. 기준: 개발계획 11.1·13·16·17장. 원문 버전/hash는 #3.

## 목표
이동 구간 또는 반복 업무 소요시간 중 한 종류를 먼저 대상으로 삼아 결과가 생기기 전에 예측을 고정하고 실제 결과와 비교한다. 예측 기록·품질 평가·제품 활성화를 구분한다. 주가·의료·관계 판단은 범위에서 제외한다.

## 예측 계약
prediction_id, issued_at, input_cutoff_at, target_window, target_type, point_estimate, interval, evidence_snapshot, model_or_rule_version, actual, evaluation_state, metric을 저장한다. 최초 예측은 불변이며 재예측은 새 version으로 남긴다. 결과가 없거나 사건이 취소되면 unscored다. confidence/interval을 근거 없는 정밀 확률로 표현하지 않는다.

## 구현 체크리스트
- [ ] 대상 한 종류와 적격 사건 기준을 고정한다. 출발/도착 또는 시작/완료가 근거로 확인되고 coverage·시간 정밀도가 충분한 사건만 실제값 후보로 사용한다.
- [ ] 예측 생성 시 원본·사건 revision·입력 cutoff·코드/모델/규칙 버전을 고정 저장하고 결과 입력 이후 소급 변경을 금지한다.
- [ ] issued_at/cutoff/target 관계와 결과가 먼저 들어온 사례를 검증한다. 외부 event timestamp만 믿지 않고 서버 접수·근거 개정 시점도 대조한다.
- [ ] 실제 결과와 예측 target을 안정 ID로 연결한다. 유사도 첫 결과로 자동 매칭하거나 중복 결과를 여러 번 채점하지 않는다.
- [ ] 결과 정정은 새로운 실제값 개정과 재평가 기록으로 남기고 원 예측을 바꾸지 않는다. 근거 삭제·철회는 적격/노출/재사용 상태에 반영한다.
- [ ] 시간 순서 평가와 개발/잠금 구간을 분리하여 미래 실제값·나중의 정정 근거가 과거 입력에 섞이지 않도록 한다.
- [ ] 최근값/중앙값 기준선과 동일 대상·동일 평가 구간에서 비교한다. 절대 오차, 편향, 표본 수, 구간 예측 제공 시 실제 포함률을 함께 기록한다.
- [ ] 초기 입력20건·결과10건은 제품 활성화 제안값으로 표시한다. 통계적 충분성 보장으로 쓰지 않으며 조건별 표본/기간/요일 차이를 공개한다.
- [ ] insufficient_data/unscored/ineligible을 0점/0분 오차로 바꾸지 않는다. baseline보다 이점이 없으면 개인화 모델을 OFF로 유지한다.
- [ ] 예측과 실제·오차를 Obsidian/타임라인에서 근거와 함께 조회할 수 있게 하되 R1 사용자 기록 화면을 예측으로 덮지 않는다.

## 구현 위치·실행 경계
기존 ledger 내 life_predictions와 실제값 개정/평가, L4 순수 예측·평가 함수, 기존 조회/게시 경로를 재사용한다. 새 모델 서버·학습 파이프라인·자동 코드수정/배포를 기본 요건으로 추가하지 않는다. 모델이 필요하면 P10 정책/비용 상한을 적용한다. 현 PR은 명세 파일 1개뿐이다.
