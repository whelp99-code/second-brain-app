# P03 — 기본 입력 adapter

명세 등록 / 구현·시험 NOT_RUN. Refs #3. 선행 P01 #5, P02 #6. R1 / REQ-01·REQ-06 / Capture / 5–8인일 추정. 기준: 개발계획 3.1·5·12·13장. 원문 식별/hash는 #3.

## 목표
허용한 메모·공유 링크·문서·AI 대화·일정·기존 메일 산출물을 동일 사건 입력 계약으로 연결한다. 원출처 식별과 수정/취소 이력을 유지하며 계정 전체를 새로 수집하는 중복 시스템을 만들지 않는다.

## 입력별 개발
- [ ] 메모/링크: 원출처 ID·발생/접수 시각·URL·본문·선택 첨부를 보존하고 위험 URL과 원문 명령을 데이터로 취급한다.
- [ ] 선택 파일/AI 대화: 기존 허용 폴더·커넥터를 우선 사용한다. 변경/축소/같은 크기 수정/삭제/재전송과 커서 재개를 처리한다.
- [ ] 캘린더: read-only export 또는 기존 승인된 연결을 사용한다. 반복 일정의 개별 occurrence, 변경/취소, 시간대, 날짜만 있는 일정, 참가자 원문을 보존한다.
- [ ] 메일/업무: 기존 Mail Intelligence의 허용 export/API 결과를 사용한다. 메시지·thread·프로젝트·원문 근거 연결을 유지하고 새 계정 수집기를 중복 구축하지 않는다.
- [ ] 통화녹음/음성: 사용자가 공유한 파일을 수집하고 전사 상태를 별도로 둔다. 미전사 음성을 기억 완료로 표시하지 않는다. 전사는 별도 flag와 P10 정책을 거친다.
- [ ] 출처마다 last_seen/covered_window/cursor/disabled/error/quarantine을 기록한다. OFF는 누락 보정 대상이 아니며 실패를 빈 입력 성공으로 숨기지 않는다.

## 커넥터 계약
`ADAPTER_ID`, `create(config)`, `source_id`, `scan(cursor)`, `next_cursor()`를 기존 SourceAdapter에 맞춘다. 파일 자동발견 규칙에 맞는 `records_life.py`, `records_calendar.py` 등은 신규 후보이며 registry `__init__.py`를 무조건 수정하지 않는다. L2는 LLM/normalize/Vault를 호출하지 않고 원본 계정에 쓰지 않는다. 여러 source ID의 cursor를 분리한다.

## 구현 체크리스트
- [ ] P00에서 외부 프로젝트의 실제 API/권한/형식을 확인해 adapter mapping과 실패 코드를 고정한다.
- [ ] P01 계약 검증→P02 영속 접수로 연결하고 원본·receipt·출처별 수량을 대조한다.
- [ ] 성공한 항목만 cursor를 전진시키고 하나의 실패가 다른 정상 항목을 제거하지 않도록 한다.
- [ ] 크기/MIME/압축/경로/symlink/인코딩/시간대 경계를 검증한다.
- [ ] 네트워크 요청은 허용된 호스트·최소 필드만 사용하며 입력 본문 지시로 범위를 넓히지 않는다.
- [ ] 제한 재시도/backoff/quarantine/수동 재개를 제공하고 무한 worker를 추가하지 않는다.

## 인수시험
AC-01/02: 중복과 날짜별 사건 보존. AC-03: 반복 일정 한 회 취소가 전체 반복을 삭제하지 않고 예정=실제로 단정하지 않음. AC-12: OFF/실패/정상 빈 입력 구분. AC-23: 악성 메모, 경로 탈출, 초대형/잘못된 MIME/압축 자료, 추적 이미지 차단. 동일 시간 항목/같은 크기 수정/순서 역전/소스별 커서 격리도 검사한다.

## 배포·제외·증거
`life_events` OFF가 기본이며 선택 출처 하나에서 시작한다. 원계정 설정/삭제·전체 8년 자료 자동 활성화·전역 화면 수집은 제외한다. rollback은 adapter 새 접수만 멈추고 receipt/원본/삭제 의도를 보존한다. 데이터 연결 수가 아니라 출처별 입력/보존/격리/처리 수, 실제 export/API fixture, 원문 연결, 테스트 로그로 인수한다. 모든 제품 검증 현재 NOT_RUN; 현 diff는 이 문서 1개다.
